# Machine Learning Laboratory Audit

## Scope

This report audits the `ml-unipr` laboratory repository against the 2026 Machine
Learning course material. The audit covers the seven lab areas, their Python
implementations, notebooks, datasets, logs, plots, and saved CSV files. It is an
evidence audit, not a claim that every experiment was rerun from a clean
environment.

The repository was inspected on 2026-08-13. No source files were changed during
the initial audit. This report is the first file added as the requested written
deliverable.

## Evidence policy

Results are classified as follows:

- **Source-verified**: the implementation and its parameters can be inspected
  directly, and the relevant data or table is present.
- **Artifact-reported**: a value is present in a log, CSV, or plot generated by
  the project, but the original run was not independently repeated.
- **Unavailable**: the required dataset, execution output, or raw result table
  is absent, so the result cannot be checked from this checkout.

The numerical values in this report are always labelled with one of these
statuses. A plot without its raw data is useful evidence of intended work, but
it is not equivalent to a reproducible experiment.

## Lab 1 - kNN and Decision Trees

### Requirements and implementation

The assignment defines a binary circle/square problem with 100 training points,
100 test points, and a dense `circleall` reference set. It asks for odd values of
`k`, comparison with a user-defined classifier, selection of the best `k` using
the test set as a validation set, and evaluation on `circleall` (handout pages
2-6).

The implementation in
`lab1_knn_dectrees/exercise1_knn.py:28-104` provides both a scratch Euclidean
kNN implementation and scikit-learn kNN. It evaluates `k` in
`[1, 3, 5, 7, 9, 11]`, selects the best value on `circletest.arff`, and evaluates
that model on `circleall.arff`. This matches the handout's use of
`circletest` as a validation set, although the code calls it a test set in some
messages.

The representation exercise is implemented in
`lab1_knn_dectrees/exercise1b_repr.py`:

- Lines 29-71 relabel the data for an inner square of side 1.76 and train a
  Decision Tree.
- Lines 78-125 compare the original `(x,y)` representation with `(x^2,y^2)`.
- Lines 129-188 create the single feature `r^2 = x^2 + y^2` and evaluate it on
  both the held-out point set and `circleall`.

The digit exercise uses 104 binary features and a final class label. The data
files contain:

| File | Samples | Features plus label |
|---|---:|---:|
| `data/Bigtest1_104.arff` | 6,024 | 104 + 1 |
| `data/Bigtest2_104.arff` | 5,010 | 104 + 1 |
| `data/circletrain.arff` | 100 | 2 + 1 |
| `data/circletest.arff` | 100 | 2 + 1 |
| `data/circleall.arff` | 2,601 | 2 + 1 |

`exercise2_digits.py:73-117` performs five stratified 66/34 random splits,
trains a default Decision Tree, and then trains on all of `Bigtest1` for the
fixed `Bigtest2` evaluation. `exercise2b_overfit.py:24-70` sweeps
`min_samples_leaf` from 1 through 30 and records training accuracy, external
test accuracy, depth, and leaf count.

### Available results

The following values are **artifact-reported**, because the CSV files were not
generated during this audit.

Source: `lab1_knn_dectrees/outputs/ex2_seed_results.csv`.

| Seed | Accuracy |
|---:|---:|
| 0 | 95.754% |
| 1 | 96.730% |
| 2 | 95.900% |
| 3 | 96.584% |
| 4 | 96.877% |
| Mean | 96.369% |

The course handout asks for repeated random splits and an average. The saved
table satisfies that part of the requested record, although the repository does
not preserve the exact stdout or the corresponding tree structures for all five
runs.

#### Minimum leaf-size sweep

Source: `lab1_knn_dectrees/outputs/ex2b_M_sweep_results.csv`.

The highest recorded external test accuracy is at `M=1`:

- training accuracy: 100.000%
- external test accuracy: 95.110%
- tree depth: 12
- leaves: 181

The table shows a monotonic reduction in complexity overall as `M` increases,
with lower test accuracy after `M=1` for this particular run. This is evidence
of a high-variance tree at `M=1`, but it does not establish that `M=1` is the
best value under another random seed or dependency version.

### Limitations and observations

1. The kNN accuracy-versus-`k` values are only stored in a plot and stdout; no
   CSV table records them.
2. The square relabelling writes new ARFF files during execution, but those
   generated files are not accompanied by a scalar results table.
3. The explanation at `exercise1b_repr.py:121-125` says that the circular
   condition becomes easier for an axis-aligned tree after using `z=x^2` and
   `t=y^2`. The exact boundary is `z+t=1`, which is oblique in `(z,t)` space.
   A standard axis-aligned tree can approximate it more effectively, but cannot
   represent that diagonal boundary exactly with one axis-aligned split.
4. The assignment uses WEKA's J48 terminology, while this implementation uses
   scikit-learn's `DecisionTreeClassifier`. The conceptual experiment is
   comparable, but the algorithms and defaults are not identical.

## Lab 2 - Iris classification

### Implementation

The assignment asks for the classic 150-sample, four-feature, three-class Iris
problem using kNN and a Decision Tree (handout pages 26-27).

`lab2_iris_classification/pipeline.py:25-63` loads the scikit-learn Iris data
and performs stratified 70/15/15 train/validation/test splitting with
`random_state=42`. `pipeline.py:70-112` trains kNN and a Decision Tree;
`pipeline.py:78-102` selects k from `{3,5,7}` using the validation set.

`lab2_iris_classification/main.py:17-118` evaluates both classifiers on the
test set and creates confusion-matrix and accuracy-comparison plots.

### Evidence status

The implementation and two PNG files are present:

- `lab2_iris_classification/outputs/confusion_matrices.png`
- `lab2_iris_classification/outputs/accuracy_comparison.png`

The numerical stdout, confusion matrices as text, and model predictions are not
stored. Therefore the method is **source-verified**, but the numerical results
are **unavailable** without running `python main.py` in that directory.

One minor code issue is that `evaluate_model` accepts `set_label` but does not
use it (`pipeline.py:119-134`). This does not change the metrics; it only makes
the helper's interface misleading.

## Lab 3 - Clustering

### Requirements and implementation

The assignment requires:

- K-Means with two clusters on standard and +50% variance Gaussian data.
- K-Means with ten clusters on 13x8 digit images, including grayscale centroid
  visualisation.
- X-Means with varying maximum cluster counts from 10 to 40.
- Mapping clusters to classes and validation on `Bigtest2` to analyse
  overfitting (handout pages 29-43).

The source implements these parts in:

- `lab3_clustering_lab/main.py:27-103` for the Gaussian experiments.
- `main.py:110-138` for digit centroids.
- `main.py:145-178` for the direct K-Means sweep.
- `main.py:181-274` for X-Means, the test evaluation, confusion matrix, and
  overfitting discussion.
- `kmeans.py:13-56` as a wrapper around scikit-learn K-Means.
- `xmeans.py:45-165` as a custom BIC-based splitting implementation.

### Missing data and conflicting logs

The required files are absent from
`lab3_clustering_lab/data/` in this checkout:

- `gausstrain.arff`
- `gausstest.arff`
- `gausstrainhv.arff`
- `Bigtest1_104.arff`
- `Bigtest2_104.arff`

Consequently, the Lab 3 entry point cannot be rerun from the repository as it
stands.

Two logs disagree:

- `lab3_clustering_lab/run_log.txt:1-117` reports all parts complete.
- `lab3_clustering_lab/outputs/run_log.txt:103-111` ends with
  `NameError: name 'k_found_list' is not defined` while calling
  `plot_overfitting_curve`.

The second log is consistent with an older version of the program. The current
source calls `plot_overfitting_curve(km_k, km_train, km_test)` at
`main.py:251-258`, so the exact run that produced each log cannot be determined.

### Artifact-reported results

The top-level log records the following values:

| Experiment | Recorded result |
|---|---:|
| Standard Gaussian K-Means | 96.00% training classification accuracy; 4 errors |
| High-variance Gaussian K-Means | 90.00%; 10 errors |
| Digit K-Means, k=10 | 94.56% training accuracy |
| X-Means, max 10 | k=10; train 94.56%; test 92.83% |
| X-Means, max 20 | k=20; train 94.56%; test 93.45% |
| X-Means, max 30 | k=40; train 94.56%; test 94.47% |
| X-Means, max 40 | k=40; train 94.56%; test 94.47% |
| Direct K-Means best recorded point | k=200; train 97.79%; test 96.47% |

These are **artifact-reported**, not independently verified. In particular,
they cannot be recomputed because the ARFF inputs are missing.

### Confirmed source defect

`xmeans.py:92-143` processes every current cluster in a pass and may accept
multiple splits. The loop condition only checks whether the current number of
clusters is below `max_clusters` before the pass starts. It does not prevent the
pass from exceeding the maximum, and the subsequent `break` does not trim the
centroid list. The recorded `max_k=30 -> k_found=40` result is direct evidence
of this defect.

The implementation should enforce the limit before accepting each split, or
perform a final assignment/centroid trim in a way that preserves valid labels.
That correction should be made before treating the X-Means comparison as a
valid parameter study.

## Lab 4 - PyTorch and FashionMNIST

### Implementation

The notebook `lab4/lab4_pytorch.ipynb` covers the requested topics from the
handout pages 44-56:

- tensor creation, indexing, element-wise operations, matrix multiplication,
  and device transfer;
- FashionMNIST download and normalization;
- DataLoaders with batch size 32;
- MLP architecture `784 -> 256 -> 128 -> 10` with ReLU activations;
- Cross-Entropy loss and Adam with learning rate `1e-3`;
- training/evaluation functions and a ten-epoch run;
- loss and accuracy plots.

### Evidence status and issues

Every code cell has `execution_count: null` and an empty `outputs` list. No
FashionMNIST data, metric history, model checkpoint, or generated plot is
included. The notebook is therefore **source-verified but experimentally
unavailable**.

The notebook has no `requirements.txt` or pinned environment specification. It
requires at least PyTorch, torchvision, matplotlib, and NumPy, and it downloads
FashionMNIST at runtime.

There is also a presentation bug in the training output at notebook source
around lines 420-429: accuracies are stored as fractions in the range `[0,1]`
but formatted with a percent sign without multiplying by 100. For example, a
fraction of `0.85` would be printed as `0.8500%`, not `85.00%`. The underlying
accuracy calculation is otherwise structurally correct.

No random seeds are set, so repeated training runs will not be bitwise
reproducible even after the notebook is executed.

## Lab 5 - Genetic Algorithms

### Requirements and implementation

The assignment covers four DEAP exercises (handout pages 63-72):

1. Minimise the specified three-variable function with floating-point and
   90-bit representations.
2. Match the binary pattern in `smiley.txt`, measure fitness evaluations, and
   study scaling and population/generation parameters.
3. Compare smart permutation and dumb coordinate representations for N-Queens.
4. Evolve a 20-move sequence for one fixed ant board.

The entry point is `lab5_genetic_algorithms/main.py`. The implementation details
are in:

- `exercise1/float_repr.py` and `exercise1/binary_repr.py`;
- `exercise2/pattern_guesser.py` and `exercise2/scaling_experiment.py`;
- `exercise3/nqueens_smart.py` and `exercise3/nqueens_dumb.py`;
- `exercise4/ant_ga.py` and `exercise4/ant_game.py`.

The README records fixed Python and NumPy seeds, and the source uses seed 42 in
each main experiment. The requirements file specifies `deap>=1.4.1`, NumPy,
and matplotlib, but does not pin exact versions.

### Artifact-reported results

The repository contains generated plots but no raw result tables or complete
run logs. The following findings are therefore **artifact-reported**:

- `smiley.txt` is a 14x16 pattern with 224 bits. The pattern-matching artifact
  records a perfect `224/224` match.
- The smart N-Queens artifact shows a zero-conflict 8-Queens solution.
- The fixed-board ant artifact reports a best score of `12/29` food cells.

The ant denominator is 29 because `generate_board` initially places 30 food
cells and then explicitly clears `(0,0)` in
`exercise4/ant_game.py:28-48`.

### Methodological caveats

1. `pattern_guesser.py:45-61` counts evaluations exactly, but
   `pattern_guesser.py:107-132` always runs the full generation budget. It does
   not stop when a perfect pattern is first found. Therefore its `Nf` is the
   number evaluated by the fixed run, not necessarily the number needed to find
   the solution requested by the assignment.
2. `scaling_experiment.py:169-197` selects the hyperparameter pair with the
   smallest mean `Nf` without requiring that all or any runs reached perfect
   fitness. A low evaluation count can therefore win despite poor matching
   quality.
3. The N-Queens source evaluates ten seeds for N in `[8,16,32,64,128]`, but no
   CSV or text table preserves the success rates. The plots alone are
   insufficient to verify the claimed threshold for the largest solvable N.
4. The Lab 5 ant implementation is a custom toroidal game starting at `(0,0)`.
   It evolves a move sequence for one board, not a general strategy. This is
   consistent with the handout's warning, but its mechanics should not be
   conflated with the separate Ant Trail lab in Lab 7.

## Lab 6 - Genetic Programming and PSO

### Implementation

The source covers the requested GP and PSO topics from handout pages 75-81:

- `lab6/ex0a.py` implements symbolic regression on a 50x50 grid with a
  protected arithmetic/trigonometric function set, ERCs, bloat control, and a
  parameter sweep.
- `lab6/ex0b.py` generates synthetic grayscale images, adds uniform +/-15
  noise, evolves a 3x3 GP filter, evaluates PSNR/SSIM, and tests on a second
  image.
- `lab6/ex1.py` is a bonus generalisation study using three image pairs.
- `lab6/ex2.py` implements a three-dimensional PSO with toroidal wrapping,
  speed limiting, global/ring topologies, parameter sweeps, and plots.

The symbolic-regression target used by the repository is

```text
sin(x) * cos(y) + log(1 + x^2) * exp(-y^2 / 10)
```

while the function set excludes logarithm and exponential operators. This is a
valid approximation design because the handout explicitly allows the student
to choose a two-dimensional function that cannot be exactly represented.

### Evidence status

No `results/` output files, numerical run logs, or result tables were present in
the audited Lab 6 directory. The source is **source-verified**, but all
performance claims are **unavailable** from this checkout.

The README describes the PSO target and the source implements the same formula
shown in `ex2.py:51-63`. Because the course PDF's extracted notation is
ambiguous around the constants in this formula, the final submission should
state the exact implemented formula rather than relying on a shorthand from
the slides.

The README claims all scripts use both Python and NumPy seed 42, but individual
PSO and GP helper calls accept seeds and some generated data use separate seeds.
This is adequate for controlled single runs but not a complete multi-run
reproducibility protocol.

The Lab 6 README contains install commands but no standalone
`requirements.txt`. The dependency set is consequently not pinned or captured
as an environment lockfile.

## Lab 7 - Ant Trail learning

### Requirements and implementation

The Ant Trail assignment requires N=10, neighbourhood radii `m=1,2`, training
sets collected from 1, 5, and 10 games, three player types, and five common
test boards. This produces 18 trained-model conditions (handout pages 83-91).

The repository has a coherent pipeline:

- `board.py` implements exactly N food cells, virtual out-of-bounds values, and
  reproducible board seeds.
- `ant.py` implements 2N moves, food collection, cell decrementing, and the
  out-of-bounds penalty.
- `ant_rec.py` records neighbourhood/action rows, either interactively or with
  an automated greedy heuristic.
- `ant_train.py` trains a Decision Tree or MLP and applies rotational data
  augmentation.
- `ant_move.py` plays a model through a full game and applies the fallback rule.
- `gp_player.py` evolves a symbolic policy with the required threshold mapping.
- `experiment.py` defines the six data configurations, three model types, and
  five fixed test boards.

### Missing experiment evidence

Only `data/test_collect.csv` is present. It contains 32 rows of a small sample
recording for a 3x3 neighbourhood. The six expected training files are absent:

```text
data/train_m1_g1.csv
data/train_m1_g5.csv
data/train_m1_g10.csv
data/train_m2_g1.csv
data/train_m2_g5.csv
data/train_m2_g10.csv
```

`results/results.csv` is also absent. The repository contains
`results/grouped_bar.png` and `results/boxplot.png`, but without the source CSV
their values, seeds, and generation provenance cannot be audited. The required
18-condition comparison is therefore **unavailable**.

### Important implementation distinction

In `experiment.py:80-93`, Decision Tree and MLP models are trained from the
collected CSV. The GP branch instead calls `gp_player.train_gp` with seeded
board simulations and does not use the collected CSV. `gp_player.py:158-162`
explicitly documents this as game-simulation training. This is a legitimate
alternative evolutionary design, but it is not the same training protocol as a
supervised GP player learned from the recorded state/action data. The report or
submission should state this distinction explicitly.

## Reproducibility assessment

### Current blockers

1. Lab 3's required ARFF data is missing.
2. Lab 4 has no executed notebook output, no dependency file, and no seed.
3. Lab 7's six training CSVs and `results.csv` are missing.
4. Lab 5 and Lab 6 do not preserve complete raw numerical result tables.
5. Dependencies are mostly unpinned. Lab 4 and Lab 6 do not provide a
   requirements file at all.
6. The existing Lab 3 logs were produced by different source versions or run
   states and cannot be treated as one consistent execution trace.
7. Output paths in several scripts are relative to the current working
   directory. Running a script from the wrong directory can create output in an
   unexpected location or fail to find data.

### Recommended environment capture

For a final reproducible submission, add one environment file at the project
level or one pinned file per lab, for example:

```text
python --version
python -m pip freeze
```

Also save:

- raw stdout for every experiment;
- CSV tables for every parameter sweep;
- the random seed and dependency versions in each result directory;
- executed notebook output or an exported HTML/PDF notebook;
- all input datasets used by the run.

## Final assessment

The project demonstrates broad coverage of the course topics and contains
reasonable implementations for supervised learning, clustering, deep
learning, genetic algorithms, genetic programming, PSO, and Ant Trail players.
The strongest directly supported results are the Lab 1 digit tables and the Lab
3 values preserved in the logs.

The project should not yet be described as fully reproducible. Before making
that claim, restore the Lab 3 datasets, execute and save Lab 4, rerun and save
the Lab 7 comparison, preserve raw result tables for Labs 5-6, and fix the
X-Means maximum-cluster handling. The distinction between source design,
artifact-reported values, and independently verified experimental results
should remain explicit in any final academic submission.
